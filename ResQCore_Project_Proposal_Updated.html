PROJECT PROGRESS DESCRIPTION
Project Abstract
(Brief restatement of your project's main goal. Max 300 words).
ResQCore is an integrated, production-grade disaster response platform engineered to handle life-threatening emergency requests when rescue squads, ambulances, medical supplies, and relief provisions are severely constrained. The foundational innovation of ResQCore is treating every incoming emergency SOS request as an Operating System Process (Process Control Block - PCB), executing priority-based preemptive scheduling rather than inefficient first-come-first-served (FCFS) processing. This guarantees that critical, life-threatening incidents immediately preempt minor reports and secure scarce rescue assets.

The complete platform encompasses three tightly integrated operational components:
  1. ResQCore Citizen Mobile App (Flutter Native): Enables impacted civilians to initiate urgent SOS calls, complete a structured 4-step emergency report (fire, flood, earthquake, medical), transmit geo-coordinates, inspect interactive hazard zones, and track responder distance in real time with local caching and dual-tier (OTP/password) authentication.
  2. RescueTeam Tactical Ops App (Flutter Native): Provides field responders and tactical commanders with role-based access, an offline-resilient CustomPaint radar canvas, live GPS fleet telemetry, dynamic incident triage (SALT/START), casualty tracking, shelter status, and emergency helicopter extraction dispatch.
  3. Central Command Center (React 18 + Vite Web Dashboard): Delivers live situational awareness for incident directors via real-time tactical maps, squad resource allocation matrices, automated priority triage queues, and a continuous Node.js Server-Sent Events (SSE) data pipeline.
On the backend, an OS algorithmic engine implements Banker's Algorithm for deadlock-free relief supply allocation and bounded-buffer Producer-Consumer queues. A relational PostgreSQL 16 + PostGIS spatial database enforces strict ACID transactions, concurrency locking (SELECT FOR UPDATE), and automated audit logs (AUDIT_LOG).

Updated Project Approach and Architecture
(Current approach, system design, communication protocols, libraries used, etc. Max 300 words).
Our architectural implementation utilizes a decoupled, real-time distributed architecture designed for ultra-low latency and mission-critical fault tolerance:
  • Client Applications (Flutter / Dart): Both mobile applications—Citizen and RescueTeam Ops—are built in Flutter using Material 3 design and compiled to native release APKs. State management is handled through Provider (RescueProvider with ChangeNotifier) and AppState, featuring local persistence (AccountStorageService), vector tactical radar drawing via CustomPaint, and audio-visual feedback.
  • Command Center Web Application (React 18 + Vite): Built using modern reactive components, Lucide icons, and optimized CSS design tokens, offering a sleek dark-mode tactical interface with dynamic live metrics, crisis radar maps, and active triage monitors.
  • Real-Time Synchronization & Communication: Implemented via a high-performance Node.js service (citizenSyncServer.js) exposing HTTP REST ingestion endpoints and persistent Server-Sent Events (SSE) streams (/api/stream) to immediately broadcast citizen SOS triggers to command operators and field rescue squads with sub-100ms latency.
  • Database & Spatial Indexing (PostgreSQL 16 + PostGIS): Features a 13-table 3NF relational schema with spatial R-Trees, enforcing relational integrity via foreign keys, cascading deletes, automated triage stored procedures (triage_incident_priority), and security audit triggers (AUDIT_LOG). Redis 7 handles rescuer GPS telemetry caching with TTL eviction.
  • OS Simulation & Algorithmic Engine: Encapsulates incident handling as OS processes with Priority Preemptive Scheduling (SALT/START), Banker's Algorithm for deadlock-free vehicle and medical kit allocation, and mutex-based concurrency locks preventing double-assignment of rescue teams.

Challenges Solved & Engineering Solutions
(Key real-world technical hurdles encountered and how our team solved them).
  • End-to-End Real-Time Synchronization: Addressed mobile-to-web synchronization by establishing a high-efficiency Node.js Server-Sent Events (SSE) bridge on port 5000, streaming citizen SOS updates to the Command Center without polling overhead.
  • Network Resilience & Offline-First Persistence: Overcame connectivity blackouts by implementing a multi-tier local caching mechanism (AccountStorageService) in the Citizen App, allowing offline report composition and automatic resubmission.
  • Double-Assignment Prevention in Fleet Operations: Eliminated concurrency race conditions when multiple operators dispatch the same rescue squad using PostgreSQL row-level locks (FOR UPDATE) and Banker's safety state evaluation.
  • Smooth Tactical Map Rendering on Low-End Devices: Eliminated costly external map SDK overheads by developing custom vector radar canvases via Flutter CustomPaint, achieving a steady 60 FPS on Android emulators and physical devices.
